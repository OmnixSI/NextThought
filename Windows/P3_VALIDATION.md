### 使用方法

1. 在“设置”点击“准备检索组件”，下载并校验模型；基础软件和本机语义推理不需要 Python。
2. 勾选“参考资料库时使用语义与关键词混合检索”，保存设置。
3. 导入资料后，在回答区勾选“参考资料库”。首次提问生成索引，此后按资料变动复用或更新；可从引用按钮查看原文。
4. 模型缺失、校验失败或推理失败时，会显示回退说明并使用关键词检索。

本机向量计算不向外发送资料；使用远程回答服务时，检索到的摘录仍按原流程发送至所选服务。引用编号和位置可追溯，不等于对任意回答的事实正确性作保证。

## P3-2 增强 OCR（CPU 可选，默认关闭）

- 采用原始 PaddleOCR-VL-1.6 / PP-DocLayoutV3 + 独立 Python 3.12 环境；paddlepaddle 3.2.2、paddleocr/paddlex 3.6.0。模型与辅助配置逐文件校验，依赖锁在 `validation/p3/ocr-requirements-lock.txt`。
- GGUF 在两个 Windows llama.cpp CPU 版本上识别失败，不用于正式处理。原始 Paddle 路线的公开合成表格、双栏和公式样本已实际推理；表格 HTML 行列正确，公式输出 sigma=F/A 的 LaTeX。双栏原结果交错，Windows 加入基于坐标/空白带的双栏校正；仅在此小样本验证，不承诺复杂报刊通用顺序。
- 三张图分别约 264.35 / 260.30 / 148.16 秒。完整资料导入约 276.32 秒，原图 SHA、页码、区块框、表格结构归档正确；取消测试约 8.05 秒终止自有进程树，暂存和资料记录无残留。固定结果保存在 `validation/p3/ocr-native-golden.json`，运行证据在 `artifacts/p3/ocr-*.json`。
- 在资料库勾选“增强 OCR”后导入图片或扫描 PDF。PDF 每次最多 10 页；每页最多 10 分钟，可取消。数字 PDF 沿用原生文字读取，基础 OCR 默认仍是 Windows OCR。发布后补充验收：一页纯图像 PDF 已走通 Windows 渲染、Paddle 识别和资料归档，耗时 442.88 秒；原 PDF SHA-256 不变，三行两列表格单元格均正确，关键词及语义检索各 2/2 命中第 1 页表格区块，缓存重载不重复建向量。这仅是一页合成扫描件，不代表真实多页复杂 PDF 的全面验收。证据 `artifacts/p3/ocr-pdf-import.json`、`ocr-pdf-verified.json`、`ocr-pdf-keyword.json`、`ocr-pdf-semantic.json`。
- 安装可选环境：源码目录 `py -3.12 scripts/prepare_enhanced_ocr.py`；发布包 `py -3.12 tools/ocr/prepare_enhanced_ocr.py`。需要已安装 64 位 Python 3.12（本机验收 3.12.10）、联网下载及数 GB 空间。只在 `%LOCALAPPDATA%/NextThought/runtimes/paddleocr-vl-cpu` 安装依赖，不改变系统 Python 包、PATH、驱动或安全设置。

## P3-4 完整句中英翻译

默认关闭，使用当前所选回答服务，开启后完整句会发往该服务。按文本语言选择中英方向；双并发、16 个待处理上限、30 秒请求超时。原文不覆盖，translations.jsonl 按句段 ID、原文 SHA 和修订号关联；异步过期修订丢弃。停止记录取消未完成译文，历史会议可点击“补译未翻译句子”。这是远程完整句翻译，未交付离线翻译或逐字同传。

DeepSeek 官方 deepseek-flash 对 4 条公开合成中英文文本的方向、数字、单位和否定含义检查通过；取消/恢复、归档/导出、旧修订晚到和备份往返通过。证据 `artifacts/p3/translation-live-v2.json`、`test-results/p3-translation.trx`。桌面使用已登录 Codex 默认模型实际点击补译、取消、重试，完成四句中英对照；已完成译文保留，未成功的句子可继续补译。随后整理纪要、通过保存对话框导出 Markdown，新建后重选历史及正常退出重启后，原文、译文、编号与纪要均完整。独立核对导出内容、句段原文哈希和原始文件未变，见 `artifacts/p3/desktop-import.json`、`desktop-translation.json`。
