# InterviewHacker 第二轮：实时性、问题识别、资料与多端

日期：2026-10-14。分支：`claude/compassionate-darwin-b9w7zx`。基于 `main` 的 `2cb05e1`。

本文档说明这一轮对代码的审查结论、已经实现的改动、仍未解决的问题和验收方法。所有核心逻辑（问题识别、流式协议解析、云端识别消息组装、手机伴侣 HTTP 解析、Office 文本抽取）都放在 `InterviewHackerCore` 并有单元测试；界面与系统集成部分只经过 macOS CI 编译，**没有在真机上做人工验收**，见第 8 节。

---

## 1. 审查结论：为什么“慢、认不出问题、不实时”

用户感知到的延迟 = 断句等待 + 识别排队/解码 + 问题判断 + 模型首字时间。上一版每一段都偏慢：

| 环节 | 原实现 | 问题 |
| --- | --- | --- |
| 断句 | VAD 静音 1.0 s 才结束一句；RMS 阈值固定 0.012 | 每句至少多等 1 s；远端声音小时整句被当成静音 |
| 识别 | Whisper 整段解码，partial 事件只更新状态文字 | 说话过程中完全看不到字；RTF>1 时排队、丢段 |
| 问题判断 | 每段最终文字跑一次字符串规则 | 只能在整段识别完成后判断；中文无问号、讲师自问自答、“我来介绍一下”等误判 |
| 回答 | 每次启动 `codex exec`，等完整消息 | 进程启动 + 登录检查 + 无流式；第一句话要等全文生成完 |

## 2. 回答端：真正的流式输出（P0）

新增 `AnswerEngines.swift` 与 Core 的 `AnswerStreaming.swift`，回答引擎三选一（设置 → 回答引擎）：

1. **Codex 常驻服务（默认）**：常驻 `codex app-server`（v2 协议，stdio 换行分隔 JSON）。应用启动和开始辅助时预热；每次回答只发 `thread/start`（ephemeral、read-only、approvalPolicy=never、关闭 shell/web search）和 `turn/start`，处理 `item/agentMessage/delta` 逐字显示，`item/completed` 的 `final_answer` 为最终文本，`turn/completed` 结束；取消发送 `turn/interrupt`。服务端发来的审批类请求一律拒绝，避免回合挂起。按 `threadId/turnId` 过滤，旧回合的晚到事件不会污染新回答。
2. **Codex exec（兼容）**：原实现保留。常驻服务启动失败或 CLI 太旧时自动回退并在界面提示。
3. **OpenAI 兼容 API（自带 Key）**：SSE 流式，适用于 OpenAI、DeepSeek、通义千问兼容模式、Kimi、Groq、OpenRouter、本机 Ollama / LM Studio。Key 保存在系统钥匙串；远程地址必须是 https，http 只允许 localhost。

界面新增“首字”与“完成”耗时；回答过程中实时渲染 Markdown（加粗、列表、代码块），提词器自动滚动到最新一行。Prompt 第 1 条改为“第一行直接给一句可以照着说出口的结论”，让流式时最先出现的就是能用的话。

## 3. 问题识别：带上下文的候选判断（P0）

新增 `QuestionIntent.swift`：

- **分类器** `QuestionIntentClassifier` 区分 **陈述 / 未说完 / 明确提问 / 请求解释 / 追问**，按证据打分：问号、英文 wh 开头与助动词倒装、中文疑问词与句末“吗/呢/对吧”、“介绍一下/讲讲/walk me through”等请求；扣分项：讲话人自述（“我来介绍”“let me explain”）、自问自答（“为什么呢？因为…”）、口头禅（“怎么说呢”“没什么”）、伪分裂句（“What we need is…”）。课程场景阈值更高，面试场景更低。
- **候选跟踪器** `QuestionCandidateTracker`：同一句话的流式修订（Apple/云端 partial、Whisper 预览）**只更新同一个候选**，不触发模型；候选在最终文字时触发，或者在高分且 1.2 s 内文字不再变化时**提前触发**；提前触发过的句子最终文字到达时不会重复回答。未说完的片段 8 s 内与下一句拼接；20 s 内完全相同的问题去重。
- **不确定区间**：分数介于两个阈值之间的句子不会自动回答，而是显示为“可能的问题”，一键回答；如果回答引擎是 API，可选“交给模型二次判断”（3 s 超时，只回答 yes/no）。
- **你正在说话时不自动插入回答**（麦克风有实时文字时）。
- **手动触发优先级**：输入框 → 最新未回答的候选 → 最近 45 s 转写。
- **评估**：`QuestionDetectionEvaluator` 输出召回率和每小时误触发；`Tests/.../QuestionIntentTests.swift` 有 60 条中英混合标注语料（含无问号中文、追问、自问自答、口头禅、讲课旁白），测试门槛为召回 ≥ 0.9、误触发 ≤ 2。语料应持续用真实（脱敏）会议句子扩充。

## 4. 识别端：更快的 STT

- **Whisper 实时预览**：VAD 每 1.5 s 新语音发出 partial，若识别队列空闲且 RTF < 0.5，就对当前片段解码一次，转录和问题候选在说话过程中更新。
- **VAD**：结束静音 1.0 s → 0.7 s；自适应噪声底（快速下降、慢速上升），基础阈值 0.008，安静的远端声音不再丢失，持续底噪会被逐渐忽略。
- **云端流式识别（显式同意 + 自带 Key）**：`CloudStreamingTranscriber` 通过 WebSocket 发送 16 kHz PCM：
  - **Soniox `stt-rt-v5`**：同一句中英混说最稳，原生端点检测，支持术语表（推荐）。
  - **OpenAI Realtime 转写**（默认 `gpt-realtime-whisper`，可填 `gpt-transcribe`）：自动 16→24 kHz 重采样。
  - **Deepgram Nova-3**：必须指定 `zh-CN` 或 `en`（`multi` 不含中文）。
  上传积压超过上限会明确报错停止，不静默丢音频。设置中的“专业词/人名”会作为各服务的术语提示。

尚未接入但值得评估的端侧方案：sherpa-onnx 流式中英双语 Zipformer（Apache-2.0，真流式，CPU 即可）、FluidAudio 的 Nemotron Multilingual 流式模型（含中文）、SenseVoice（非流式但很快，适合作为句末二次解码）。

## 5. 资料、Prompt 与会前准备

- 新增 Word（.docx/.doc）、PowerPoint（每页幻灯片一页，便于引用 p.N）、Excel、ODT、HTML、图片导入；**扫描版 PDF 与图片用 Vision 端侧 OCR（简体中文 + 英文）**；GB18030 文本自动识别；支持拖放。
- **预设**：保存场景、样式、回答要求、背景说明和（可选）已解析的文件文字，下次一键恢复。
- **Prompt 模板**：面试 / 会议 / 课程各一份可编辑的起点。
- **预测可能的问题**：根据资料生成最可能被问到的 8 个问题和要点。
- **一键调整回答**：更简短、展开、举例、STAR、英文版、中文版、澄清问题、我可以反问；⌘⇧1 直接“改短”。

## 6. 显示位置、提词器与不被共享捕获

- 提词器改为半透明材质面板：不透明度、字号、位置预设（摄像头下方 / 底部 / 右侧）、**鼠标穿透**（⌘⇧K）、历史回答翻页（⌃⌘← / ⌃⌘→）、实时显示当前候选问题和首字耗时。
- **一键隐藏全部窗口**（⌘⇧\\，再按恢复）。
- **共享可见性测试**：用与 Zoom/Teams/Meet 相同的 ScreenCaptureKit 截整屏，直接看提词器是否会被拍到。
- 诚实说明：`sharingType = .none` 对旧式捕获和“只共享某个窗口”有效，但 Apple 官方表示没有保证排除录屏的公开 API，macOS 15 起部分基于 ScreenCaptureKit 的整屏共享 / 录屏仍可能拍到。最稳妥：只共享会议窗口或标签页，或者把回答放到手机上。
- 回答使用者需遵守会议、课程、考试和面试方的规则与录音同意要求。本应用不宣称“不可检测”。

## 7. 手机伴侣

设置 → 手机伴侣开启后显示二维码，手机相机扫码即可（无需安装 App）：

- 实时显示当前问题与**流式回答**，可调字号；按钮：回答、更简短、举例、英文版、上一条/下一条、取消。
- 屏幕共享完全看不到手机，是整屏共享时最可靠的显示方式。
- 安全：默认关闭；每次开启生成 128 位随机配对码，所有请求常数时间校验；只同步当前回答状态，不同步转录、资料、截图；最多 4 个连接；局域网明文 HTTP，请在可信网络使用。
- 手机作为**麦克风/识别端**未实现：浏览器在非 HTTPS 局域网页面无法调用麦克风，且手机拿不到 Mac 播放的系统音频。需要原生 iOS App（后续）。

### 建议的实机验收清单

- [ ] 设置 → 回答引擎选“Codex 常驻服务”，手动提问，确认逐字出现、首字耗时显示；取消后旧回合不再写入。
- [ ] 断开/卸载 Codex 后确认回退到 exec 或给出明确错误。
- [ ] API 引擎：DeepSeek / Ollama 各测一次流式、错误 Key 的报错。
- [ ] 中文无问号提问、“那缺点呢”追问、讲师“为什么呢？因为…”自问自答、自己说话时不自动回答。
- [ ] 云端识别：Soniox 中英混说；拔网线时的报错。
- [ ] 提词器：穿透、透明度、⌘⇧\\ 隐藏、共享可见性测试分别在“共享整屏”和“共享窗口”下观察远端画面。
- [ ] 手机伴侣：扫码、流式显示、按钮遥控、关闭后旧链接 403。
- [ ] 导入扫描 PDF、PPTX、DOCX；保存/恢复预设；预测问题。

## 9. 下一步建议

1. 用真实（同意并脱敏）的会议录音扩充问题识别语料，报告召回与每小时误触发，再调阈值。
2. 端侧真流式中文：评估 sherpa-onnx 双语 Zipformer 作为 partial，SenseVoice 作为句末修正。
3. 会后总结：基于已保存的问答与转录生成纪要和行动项。
4. 原生 iOS 伴侣（HTTPS/配对证书），让手机也能采集现场（线下会议）声音。
5. 资料检索从词面升级为混合检索（NLEmbedding 或小型本地向量模型），先建检索测试集。
