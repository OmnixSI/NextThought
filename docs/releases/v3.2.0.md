# NextThought v3.2.0

这一版修的是实际使用里的四个问题：资料导入又慢又容易失败、讲稿跟不上、纪要太乱、导出的 Markdown 后缀不对。

## 资料导入

- 幻灯片和论文里的照片、图表不再让整份文件失败。本机识别模型遇到没有文字的图片会一直写到上限，旧版本把这当成错误，报“区域文字超过生成上限”，整份文件作废。现在图片里有字就读字，没有就跳过，页眉图、页脚图和印章不读。
- 幻灯片的嵌图先快速看一眼有没有文字再决定是否识别；模板里每页都有的图标只算装饰，同一张图只读一次；图标读出来的单个字符不进资料。
- PDF 的文字层重新整理：去掉每页重复的页眉、页脚和页码，把排版切断的句子接回去，把章节标题标出来。一份 27 页的报告原来是 27 个整页，现在是 154 段正文和 38 个章节标题，引用会带上“1 Introduction > 1.1 …”这样的位置。
- 检索片段按页和章节合并。一份 39 页的幻灯片原来切成 411 个片段（很多只有两三个词），现在是 130 个，生成向量的时间相应缩短。
- 已经导入过的资料不会自动重做。想用上新的整理方式，把文件重新加一次；之前导入失败的文件点“重试”即可。

## 会中查资料

- 语义查找在会中一直退回关键词查找的问题已修复。查询设了 1 秒上限，超时会把已经加载好的模型一起关掉，下一个问题又要重新加载，于是整场会议都在超时。现在模型加载期间用关键词查找，加载完成后一直保留。

## 讲稿跟随

- 你在 PowerPoint 里写的演讲备注就是讲稿：翻到这一页，提词岛逐句显示你自己的备注，讲过的变灰，下一句高亮，最后一行是下一页的标题。不再用模型另写一份要点，也不用等。没有备注的页面仍由回答引擎写要点。
- 匹配幻灯片只看观众能看到的内容，演讲备注不参与；英文按整词匹配，每页都有的页脚和作者名几乎不计分。用一份 39 页的真实幻灯片测试，屏幕文字丢掉一半时仍认对 37 页，没有认错的。
- 屏幕读不到或认不出时有三条后路：上一页的讲稿先保留一会儿；你念到下一页讲稿的头两句，提词岛跟着翻页；也可以用 ⌃⌥, 和 ⌃⌥.（或提词岛上的箭头）手动翻页，共享屏幕换到别的幻灯片后恢复自动跟随。
- 正文很多的 PDF（报告、论文）不再被当成幻灯片。
- 模型写的讲稿要点保存在本机，排练时生成过的页面，正式讲时直接显示。

## 纪要

- 每条一句话、一件事，不超过 50 个字，不再复述谁先说了什么。
- 要点按议题归组，议题按讨论的先后排列；认真讨论过的议题都会出现。
- 未决问题、风险这类部分最多 5 条，写成一个待回答的问题；“尚未明确”“会议未确认”不再散落在每一条后面。
- 同一件事只写一次；一句话总结不带时间点。
- 提到人时全篇用同一个称呼。

## 其他

- 导出 Markdown 的文件后缀是 `.md`（原来是 `.markdown`），文件名里带点号时不会被截断。

## 尚未实测

讲稿跟随在真实演讲里的表现还没有验证：匹配和按语音翻页用真实幻灯片的文字做了模拟测试，没有接真实的屏幕共享和现场语音。纪要的新写法用一场真实会议的转写生成过一次，其他模板（面试、组会、答辩）只检查了提示词。
