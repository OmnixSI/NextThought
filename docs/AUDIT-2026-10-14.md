## 2. 为什么原来不够实时

原链路是：系统音频 → VAD 等待整段结束 → Whisper 解码 → 规则判断问题 → 启动 Codex CLI → 等待完整回答。

因此，用户感受到的延迟不仅是 STT 推理时间，还包括断句等待、识别排队、问题判断和模型回答等待。把音频切得更短，不一定让链路更快：当解码吞吐不足时，更多请求反而可能加重排队。

| 发现 | 代码位置 | 本轮处理 | 仍需处理 |
| --- | --- | --- | --- |
| VAD partial 事件只更新状态，没有进行转写，界面并不是真正的逐步识别 | AppState.receiveSpeechEvent、VoiceActivitySegmenter | 新增 Apple 流式路径，界面明确区分“流式”与“分段” | Whisper 默认路径仍是整段解码 |
| Whisper 处理速度不足时，队列可能遗漏音频 | AppState.enqueueFinal、LocalWhisperService | 展示处理耗时、实时因子 RTF 和遗漏段数 | 必须在目标设备上测吞吐并选择合适引擎 |
| 相似问题可能在整个会话被持续去重 | QuestionDetector | 改为限时精确归一化去重，过期片段不再拼接到后来的话 | 仍是启发式检测，不是语义分类器 |
| 导入入口隐蔽，导入新文件覆盖旧资料 | ContentView、AnswerPromptBuilder | 独立资料页、多文件、逐份启停、相关片段检索 | Office/OCR、持久工作区和语义检索尚未加入 |
| 过长转录截取前缀，可能保留旧内容而丢失最新内容 | AnswerPromptBuilder | 保留最新转录尾部，限制各类上下文预算 | 还需要重要事实摘要和回答时效策略 |
| 暂停、停止、新会话与异步回调之间存在状态混用风险 | AppState、AudioCaptureService | 会话代号隔离、清理旧答案、取消与限时清理 | 要做真实设备长时并发验收 |
| 每次回答启动 CLI，并等待完整代理消息 | CodexBridge、CodexEventParser | 短期登录状态缓存、非主线程等待、完成消息及时显示 | 尚未实现常驻 App Server 和真正的 token delta |
| 固定小窗口同时承担配置、转写和读答案 | ContentView、InterviewHackerApp | 可调整主窗口、内容层级重排、独立提词器 | 视觉和辅助功能仍需人工验证 |
| Whisper stderr 可能包含解码文字 | LocalWhisperService | 不再持续写入原始 Whisper stderr | 已有旧日志不会自动删除；整个数据保留策略待完善 |

实时因子定义：`RTF = 识别处理秒数 / 输入音频秒数`。它大于 1 时，持续输入容易积压。新增指标描述实际观测，不代表已将 RTF 降到某个值。

## 3. 本轮已实现的使用体验

### 3.1 两条语音识别路径

原有 Whisper 路径保留，默认设置不强制迁移。它支持原来的自动语言选择，但仍是分段识别。

新增 Apple SpeechAnalyzer / SpeechTranscriber 路径，要求 macOS 26 和可用设备/语言资源，编译时需要支持这些接口的工具链。设置中明确选择中文或 English；暂不提供此路径的自动中英混合识别。首次使用可能下载语言资源，随后由端侧引擎识别；失败时提示用户切换，不会偷偷把音频传到云端。

Apple 路径分别处理可修订文字和最终文字，音频输入采用有界缓冲。缓冲积压超限时明确报错，而不是把遗漏内容伪装成完整转录。新会话代号防止旧回调污染下一场会话。相关平台能力参考 [Apple WWDC25 SpeechAnalyzer](https://developer.apple.com/videos/play/wwdc2025/277/)。

**这证明了接口已接入并编译，不证明它在每台 Mac 上一定更快或更准。** 需要按照第 8 节的同音频基准验收。

### 3.2 手动触发与快捷键

“回答最新转写”不依赖自动问题规则。输入框有内容时优先使用输入；否则使用当前可修订文字和最近转录。正在自动回答时，可以用手动请求替换它。

| 默认快捷键 | 动作 |
| --- | --- |
| ⌘⇧Return | 回答最新转写 |
| ⌘⇧P | 暂停 / 恢复聆听 |
| ⌘⇧O | 显示 / 隐藏提词器 |
| ⌘⇧Esc | 取消当前回答 |
| ⌘⇧M | 开始 / 停止辅助 |
| ⌘⇧R | 重新生成上一题 |
| ⌘⇧A | 窗口截图 |
| ⌘⇧S | 区域截图 |

设置中可录制自定义组合键，检查重复绑定，显示系统注册冲突，并恢复默认设置。

有一个明确边界：**已有识别文字时，一次触发即可生成；Whisper 尚未产生任何文字时，首次点击只会提交当前语音段，文字出来后需要再点击回答。** 不将“强制结束音频段”描述成瞬间理解尚未识别的声音。Apple 路径已有暂定文字时可直接使用。

### 3.3 会话资料与 Prompt

资料页支持多份 TXT、Markdown、CSV、JSON、RTF 和文字 PDF，允许逐份停用、启用和移除。可选择会议、面试或课程场景，以及提词要点或详细解释样式。单独的回答要求字段可填写语言、范围、表达方式；它和文件正文分开处理。

限制：最多 12 份；单文件 20 MiB、200 页 PDF、20 万字符；工作区总计 60 万字符。扫描 PDF、加密 PDF、DOCX/PPTX 目前不直接支持，请先转换为可提取文字的格式。

文件在本机解析和分块；用中文双字片段、英文词及词频权重检索相关内容。每次最多提交 8 个片段，带文件名和页码。答案 Prompt 要求根据资料陈述时标注来源，界面提供“最近提交的资料片段”供用户核对。

**这是轻量词面检索，不是向量语义检索；引用是生成要求，不是已经完成的引用真实性校验。** 同义词、跨语言问答和间接指代可能检索不到正确段落。

导入文件只保留在当前应用进程内存，退出后需重新导入；背景说明和回答要求存储在本机。更换会议时不会自动删除全部工作区资料，应检查启用范围。检索片段和相关转录会交给 Codex 回答，因此“文件本地解析”不等于“回答也完全离线”。

### 3.4 工作台与提词器

主窗口改为可调整尺寸，默认 620×780，最低 520×600。资料入口和音频来源更明显，建议回答优先于转录呈现；转录跟随滚动可关闭。错误改为可关闭的页面提示，而不是打断阅读的模态弹窗。

新增原生非激活浮动 NSPanel：可以拖到摄像头附近或第二块屏幕，保存位置，调整字号，单独显示提词器，返回工作台，取消生成和触发回答。显示时不主动抢走会议软件的键盘焦点。

屏幕捕获排除选项默认关闭，开启后仅做 best-effort 的窗口共享属性设置。**不能保证 Zoom、Teams、Meet、OBS、截图工具或系统录屏不捕获。** 应优先只共享需要展示的窗口，并使用另一台设备检查远端实际画面。不要把此选项用于规避录制同意或考试规则。

### 3.5 稳定性和隐私修复

新会话清除旧问题、回答和截图；暂停时取消生成，不对清理中的语音继续自动回答。Whisper 排队遗漏会计数提示，停止清理不再无限等待。模型使用或下载期间禁止删除。下载取消发生在开始之前时，也会被正确处理。

连续语音切段的半秒重叠不会独立变成新的话语；只有确有音频时间重叠时才修剪转录重复前缀，后来的真实重复提问不会直接丢弃。问题去重窗口为 15 秒，未完成片段过期时间为 8 秒。

截图显示器切换增加异步结果校验，避免上一块屏幕的结果覆盖新选择；移除空显示器列表的固定下标访问。构建签名脚本用 macOS 自带 grep 代替对额外 ripgrep 的依赖。

## 4. 更快 STT 的选择：不要只按英文跑分决定

下面是截至审计日核验的候选，不是本软件的速度排名。除 Apple 和原有 Whisper 外，**本轮没有接入这些供应商或模型**。

| 路线 | 本项目适配判断 | 注意事项 |
| --- | --- | --- |
| Apple SpeechAnalyzer | 本轮已接入，适合作为受支持 Mac 的端侧流式候选 | 语言和设备需要检测；本实现中文/英文明确选择；需实测 |
| 原有 whisper.cpp | 兼容保底、保留自动语言路径 | 不把分段接口当作原生流式；必须观察 RTF 和积压 |
| FluidAudio 的 SenseVoice / Paraformer | 下一轮本地中文候选，值得做同一语料 A/B | FluidAudio 的 Parakeet EOU 流式模型是英文专用，不能拿来直接解决中文；分别复核模型与库许可证 |
| Soniox stt-rt-v5 | 可选云端候选，重点验证中英混合、多人和专业词 | 当前型号是 v5，不按旧 v4 配置文档选型；云上传须明确同意，另测网络与成本 |
| OpenAI gpt-live-transcribe | 可选云端增量转写候选 | 按当前文档做 PCM 格式和客户端端点控制；不要假设附带说话人标签 |
| Deepgram Nova-3 | 可验证普通话专用配置 | 不混淆普通话支持与中英混合配置；Flux 多语言清单不能当成中文支持证明 |

来源：[FluidAudio 官方仓库](https://github.com/FluidInference/FluidAudio)、[Soniox 模型清单](https://soniox.com/docs/stt/models)、[OpenAI 实时转写文档](https://developers.openai.com/api/docs/guides/realtime-transcription)、[Deepgram 模型与语言](https://developers.deepgram.com/docs/models-languages-overview)。

建议选型顺序：先在目标 Mac 实测 Apple；中文或混合识别不达标时，再比较本地中文模型与一个明确授权的云端方案。不一次加入大量供应商设置，也不把服务端完整文件上传伪装成实时 WebSocket。

## 5. 下一轮最值得投入的工作

### P0：真正的回答流式输出和延迟控制

当前仍通过 Codex exec 等完整消息。短期登录缓存只减少重复准备，不能消除模型生成等待。下一步应评估官方常驻 [Codex App Server](https://developers.openai.com/codex/app-server)：初始化后复用进程，使用 thread/turn，处理 `item/agentMessage/delta`、完成与中断事件。**该后端尚未实现。** 需要按安装的 Codex 版本固定协议和测试，不读取或绕过登录凭证。

回答调度应区分手动请求和自动请求：手动优先；旧自动任务取消或淘汰；新问题完成前保留可读的上一条回答；禁止跨会话结果提交。测试时分开记录“首个有用句子”和“全文完成”，不要只统计 HTTP 返回或进程退出。

### P0：问题识别从字符串规则升级为可评估的事件流程

当前修复的是误去重和片段拼接，不代表已经解决所有问题识别。下一步使用带时间范围和版本号的问题候选，区分仍在讲话、候选形成、稳定确认、生成中和完成。流式文字修订只能更新同一个候选，不能每个 partial 都启动一次大模型。

轻量规则可保留为第一层；第二层用短上下文分类“明确问题 / 请求解释 / 陈述 / 未完成”。分类器输入应包含前文和音频来源，输出问题文本及对应转录范围。需要专门标注中文无问号、反问、追问、复合问题、讲师自问自答和问题被回答后再次提及的例子。核心指标是漏检率、误触发次数和触发延迟，不是演示里是否出现问号。

### P1：资料引用质量和可切换工作区

增加命名工作区和显式会话作用域；持久化资料时提供加密、保留时间和彻底删除。加入中文/英文混合语义检索和重排前，先建立检索测试集，确认其确实优于当前词面索引。增加 DOCX/PPTX 导入、扫描 PDF 的可选 OCR、引用后验核验和无依据提示。代码与公式需要专用显示，不应只依赖普通 Text。

### P1：手机先做显示端，再考虑采集端

第一阶段仅同步已生成答案和必要的会话状态，不把手机当作任意远程控制入口。建议局域网配对：二维码携带短期随机配对信息和服务器身份，Mac 明确确认，使用经过验证的加密连接，支持连接吊销、会话结束失效、序号和断线重连。默认关闭服务；禁止暴露无需鉴权的监听端口，也不默认同步简历、全部转录或截图。

第二阶段再考虑手机麦克风与端侧 STT。手机并不天然取得 Mac 里播放的系统音频；戴耳机时，旁边手机的麦克风不能解决远端会议音频来源。手机锁屏、浏览器后台、录音权限和网络中断都需要单独设计与验收。**本轮没有手机配对、网页显示端或手机录音实现。**

### P2：适合会议/课程的长期体验

在主链路达标后加入会后摘要与行动项、章节书签、重点词纠错、双语字幕、回答简短/展开切换、成本显示、会话导出、可配置数据保留和辅助功能验收。加入麦克风或说话人分离时，必须处理回声、重复采集和说话人归属，避免软件回答用户刚刚念出的自己的答案。

## 7. 如何在 Mac 上验收这一分支

先保存自己的未提交改动，然后在现有克隆中执行：

```bash
git fetch origin
git switch --track origin/improve/realtime-workspace
# 本地已存在该分支时改用：git switch improve/realtime-workspace
swift test --disable-sandbox
bash scripts/build-app.sh
open dist/InterviewHacker.app
```

构建脚本需要对应的 Xcode 工具链和 cmake。它还会构建仓库内的 Whisper 运行时并进行本地签名；CI 中的 Swift 构建成功不能替代这条完整安装路径验收。不要把本地签名开发包当作经过开发者公证的公开发行包。

启动后先确认屏幕录制权限和音频来源；资料页添加当前会议的文件，填写回答要求；设置中选择转写引擎与语言。Apple 新路径必须主动切换，保留的默认 Whisper 不会自动变成流式引擎。通过提词器读答案，使用 ⌘⇧Return 验证手动触发。

无有效 Codex 登录时可以继续转写，但不能生成回答。相关转录/检索片段交给 Codex 的数据边界应在实际使用前告知用户；会议参与者的录制和 AI 使用要求应得到遵守。

建议记录：第一段暂定文字延迟、说话结束到最终文字、CER/WER、专业词错误率、问题召回率和每小时误触发、问题结束到首个有用回答、全文完成时间、RTF、队列长度、音频遗漏、检索来源命中、CPU/内存和会话长度。用中位数及 P95，不只报告最优案例。

## 9. 合并建议

保留为草稿 PR，完成关键实机验收后再 squash 合并。不要同时替换语音、答案协议、存储和手机网络层，以免不能归因回归。

本轮交付的核心是：可编译的端侧流式候选路径、可控手动触发、多文件上下文、独立提词器和一组明确的稳定性修复。下一轮第一优先级是**回答端真正增量输出 + 问题事件调度 + 目标设备端到端测量**，而不是继续增加装饰性功能。
