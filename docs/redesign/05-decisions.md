# 决策记录

按时间顺序记下这轮重新设计里做过的决定，以及放弃的方案和原因，方便以后回头看“为什么是现在这样”。

| # | 决定 | 放弃了什么 / 为什么 |
|---|---|---|
| 1 | 设计系统先从仓库同步一份，再精简 | 直接照搬代码会把“乱”也搬过来：28 个颜色、17 级字号、10 个组件 |
| 2 | 第一次精简：克制的原生 macOS，主色纯色 #5146C8 | 被第 4 条取代。对应代码在分支 `claude/design-system-v2`，**已作废** |
| 3 | 每个区域最多 1 个主按钮 + 3 个次要操作，其余收进“…” | 原来助手页空闲时常驻约 30 个控件，同一个动作在一屏里有 2–4 个入口 |
| 4 | 视觉语言改为“纸与墨”：暖白纸 + 近黑墨，主按钮用墨色，**紫色只代表 AI**，标题用衬线体，大量留白，安静的动效 | 第 2 条的配色“没有高级感”。紫色到处都是会失去意义；墨色主按钮更稳，紫色留给 AI 产出的内容，用户一眼能分清哪些是 AI 给的 |
| 5 | **一场会议 = 一页**：准备 → 进行中 → 纪要 | 原来拆成“场景 / 助手 / 记录”三个标签，用户要自己来回跳 |
| 6 | 完整流程和“立即记录”是同一个流程，区别只是做不做“准备” | 不做“完整模式 / 简单模式”的全局开关，免得用户搞不清自己在哪个模式 |
| 7 | 会中进入专注模式：隐藏侧边栏、首页、资料夹、设置；不再提供布局预设和弹出模块 | 会中注意力只应该在这场对话上；提词器已经承担了“单独一个小窗”的作用 |
| 8 | “提词 / 只记录”开关代替设置里的“自动回答”开关 | 同一件事两个开关会互相矛盾 |
| 9 | 模型、快速模式、联网、回答长度集中到“回答设置”菜单，在会中点模型标签打开 | 这些都影响回答，会中可能要随手改，但平时不需要占顶栏的位置 |
| 10 | 手机状态：只在开启了手机伴侣时显示，绿点 = 已连接 | 代码里有连接数，但原来的界面看不到 |
| 11 | 日历、邮箱现在只读会议的时间和主题 | 自动找资料、读取参会人放到以后。先把最简单、最确定有用的做好 |
| 12 | 邮箱第一版不接 | Apple 邮件扩展只能处理新收到的邮件，搜不了历史；账户授权的工作量和隐私成本都高 |
| 13 | 中英文切换 = 整个 App 的系统语言；新界面从第一步起就中英一起做 | 将来有海外用户。等界面定型再翻译会翻两遍 |
| 14 | 系列：二面自动接上一面的资料、复盘、经验，勾选带入 | 不让用户每一场都重新导入。代码里的“场景”已经有这些数据，只是改个名字 |
| 15 | 会议类型 8 种（默认“通用”）加自定义，平铺成标签，按日历标题自动猜 | 原来只有 4 个选项不够；用下拉菜单要多点一次，而且看不到有哪些选项 |
| 16 | 声音默认“电脑声音”（全部系统声音）+ 麦克风，不依赖识别会议软件 | 会议软件太多，无法逐一适配，也不一定识别得出 |
| 17 | 支持线下会议：只用麦克风，转写标“现场”；纪要只在原话点名时写人名 | 不保存录音就没法按声音区分说话人，宁可不写人名也不张冠李戴 |
| 18 | 会后纪要用单独的模型和流程：AI 校对转写 → 按场景模板整理 → 核对引用和日期 | 会中追求快，会后追求准确和详细 |
| 19 | “精修”不重新识别、不保存录音，只把完整转写交给 AI 按上下文纠错 | 现有识别准确率已经够高；不改变“音频只在本机识别、不保存”的承诺 |
| 20 | 每个纪要模板都有“不足”这一部分（答得不好 / 讨论不透彻 / 风险和未决） | 这是纪要最有价值、也最容易被普通摘要漏掉的部分 |

## 还没定的

- 自定义纪要模板要不要支持分享和导入。
- 跨系列的题库搜索（例如字节和腾讯的后端面试共用题目）。
- 手机伴侣网页的视觉，是否也换成“纸与墨”。
