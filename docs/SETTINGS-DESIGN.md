# 设置与新手引导

## 产品主流程

InterviewHacker 是开会时的实时助手。核心流程是（重新设计后，见 [docs/redesign](redesign/README.md)）：首页“新会议”进入准备页（会议类型 → 接着上一场 → 资料 → 开始前检查）或直接“立即记录” → 会中专注模式（提词 / 只记录）→ 结束后同一场会议自动变成纪要。录屏和麦克风权限在第一次开始时就地申请；新手引导不再在启动时弹出，从 设置 → 基础 打开。手动输入是辅助入口，不替代核心语音准备。

实时语音与对话回答是必需能力。OCR 增强和向量嵌入是可选资料能力：不安装它们，也能运行核心流程。默认资料处理使用系统识别与关键词查找。

## 全部设置的分层

默认进入简洁模式，右上角固定显示一个“高级设置”开关。开关控制复杂控件的可见性，不清除已选服务、模型、索引或资料，不停止已启用的功能。当前生效的联网、复盘等行为仍以简短状态说明展示。

| 分组 | 默认显示 | 打开高级设置后显示 |
|---|---|---|
| 基础 | 核心准备状态、新手引导、回到首页、**语言**（跟随系统 / 简体中文 / English，切换后自动重新打开，会议中不可切换）、备份与更新入口 | 环境配置/修复、完整检查清单、外观、置顶 |
| 识别 | 声音来源（默认“电脑声音”，即整个屏幕的系统声音）、音频权限、麦克风、当前引擎就绪/下载；已选云端或系统引擎的必填项 | 更换引擎、模型型号、整句精修、专业词、预热、回声参数、屏幕感知、演示文稿跟随、回答进度 |
| 回答 | 对话服务、登录状态、回答模型、API 必填地址/密钥/模型、连通性测试、联网状态；“自动回答”只剩说明：由会中顶栏的“提词 / 只记录”决定，默认值来自会议类型 | 推理强度、Fast、API 多预设管理/模型列表、联网服务细项、问题识别二次判定、Codex 传输方式 |
| 纪要 | 纪要模型（默认自动选最强模型）、推理强度（默认“高”，从不开 Fast）、会后自动整理、纪要语言（默认跟随界面）、各类型的默认模板、自定义模板（复制 / 编辑 / 删除） | — |
| 资料 | 当前读取方式、系统/本机增强/Codex 的就绪状态和取舍、缺失组件合计下载量、按用途一键准备、关键词/语义增强、Office 支持 | 逐组件校验/修复/删除、固定来源与许可、严格/降级策略、Codex OCR 参数、索引重建 |
| 提词器 | 打开、位置、字号、共享排除及实际限制 | 不透明度、背景、鼠标穿透、共享测试、仅显示提词器 |
| 技能 | 默认侧栏收起；高级开关打开后进入 | 技能导入/编辑、全局或场景作用范围 |
| 数据 | 从基础页直接进入本机记录、普通导入导出、备份状态与立即备份 | 自动复盘/经验回写、密钥导出、导入设置选项、备份策略与历史恢复 |
| 更多 | 从基础页直接进入版本与更新；授权问题发生时显示必要帮助 | 更新渠道、自动检查策略、访问细项、签名修复、快捷键、手机伴侣、性能 |

简洁模式的 API 模型名仍必填可编辑，不会被藏进高级设置。简洁模式导出不包含密钥，即使此前曾在高级模式勾选密钥导出。隐藏高级设置不会把现有高级功能关闭；用户可以再次打开开关调整。

## 资料能力的取舍

| 选择 | 收益 | 代价与边界 |
|---|---|---|
| 系统识别 | Mac 自带、离线、不下载 OCR 权重 | 复杂表格和公式可能丢失结构，数字仍需核对 |
| 本机增强 | 面向扫描件、表格和公式，本机处理 | 识别/版面模型加共用组件最多约 1.42 GB，使用内存，仍可能识别错误 |
| Codex 原文件代读 | 不下载 OCR 权重，可读原文件 | 需已登录 Codex、约 186 MB 共用组件与网络，使用账号额度，耗时受网络影响 |
| 关键词查找 | 无需向量模型和预先建索引，准备快、占用少 | 同义表达、跨段答案可能漏检 |
| 语义增强 | 补充按含义查找，保留关键词兜底 | 模型加共用组件最多约 835 MB，首次建索引、占存储与内存，仍可能漏检 |

共用组件只安装一次，下载量按当前缺少的组件计算。选择、组件已安装、真正就绪/生效分别显示；依赖不齐全不会标为可用。安装失败保留当前方式，取消后可复用已校验文件；准备期间改选，晚到结果不能覆盖新的选择。

当前关键词和语义两种模式都只把相关片段带入回答上下文，关闭向量不等于发送全文。把所有资料都发送会增加用量和等待，也可能超过上下文上限；不能把当前实现描述成“关闭向量后全文都会被读取”。

## 会中可以改的设置

会中不切换主窗口：⌘, 打开单独的设置窗口。影响回答的选项集中在顶栏模型标签打开的“回答设置”菜单：模型（当前服务下的模型列表；切换 Codex / API 服务仍去设置）、快速模式（只在 Codex 且模型支持时出现）、联网（不联网 / 自动判断 / 每次都查）、回答长度（要点 / 详细）。修改从下一个回答开始生效；回答长度同时存回系列。

## 会后纪要

纪要不复用会中回答的模型设置。流程：校对转写（结合资料里的专有名词纠错，结果单独保存在 `notes.json`，转写文件不变，可以逐条撤销；不重新识别，不保存录音）→ 按模板整理（每条带原话时间点，长会议分段后合并）→ 核对（删掉没有时间点或时间点附近没有原话的条目；相对日期按会议日期换成具体日期；不确定的标“待确认”）。纪要模型没有按 JSON 回答时，退回原来的 Markdown 摘要，保证会后仍有内容。面试复盘的“待改进”题和更好的答法写进系列题库；学术、工作会议、客户沟通、小组讨论的下一步 / 待办 / 承诺 / 分工写进系列经验（带前缀，例如“[待办]”），供下一场“接着上一场”带入。

## 五步引导与版本

1. 认识实时语音对话助手及完整流程。
2. 准备语音识别、会议音频与麦克风权限。
3. 连接对话回答服务。
4. 了解 OCR/向量的可选取舍，可以明确采用无需额外下载的资料方案。
5. 确认核心能力就绪，选择会议声音来源，开始实时辅助。

最后一步要求语音、所需权限、对话服务和音频来源就绪，OCR/向量不是门槛。成功开始后才记为完成；“稍后继续”只关闭引导，保留进度，不标记完成。

重新设计后启动时不再自动打开引导（权限在第一次开始会议时就地申请），以下版本记录逻辑仍保留，供手动打开和自检使用。引导完成版本按主次版本记录：首次安装、1.7 → 1.8、1.x → 2.0 自动完整展示；同一功能版本内的补丁不重复展示。进行中的引导可继续，新功能版本从第一步开始，也能手动重新打开。备份不携带完成标记，因此恢复旧资料不会绕过新安装引导。

## 验证范围

- 单测覆盖所有依赖组合、核心语音/对话不可绕过、无 OCR/向量仍可启动、首次/功能/补丁版本策略和备份标记过滤。
- `document-setup` 离线自检覆盖组件复用、取消、晚到选择保护、引导重置/继续/完成、高级模式持久化且不清空配置。
- 原有语音与回答管线保持复用。UI 检查使用独立 bundle identifier 与测试目录，不替换日常安装或修改其资料。
