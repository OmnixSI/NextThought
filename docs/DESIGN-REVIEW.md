# InterviewHacker 设计与交互审查

审查日期：2026-10-23。审查者：Astra 设计审查代理。范围：macOS 会前准备、会中回答与依据、屏幕来源、手机配对，以及 iOS / Android / 网页伴侣。

本报告以当前源码为主要依据，辅以仓库既有 `docs/screenshots/assistant-light.png`、`materials-light.png`、`settings-dark.png` 与 `.local/stability/relay-browser-qa.png`。既有截图只用于观察视觉层级，不能证明新增功能或真机行为。尚未进行 iOS / Android 真机、VoiceOver / TalkBack、动态字体与弱网手动验收。首轮审查未修改源码；随后按主代理协调实施下述 UI 改动。构建与真机结论以末节记录为准。

## 判断与优先级

总体方向保留：原生控件、明确回答主区、紫蓝品牌点缀、按任务组织设置。现在最需要完善的是状态信息与操作层级；不建议增加装饰插画或再叠加玻璃效果。

本次没有足够证据认定视觉层面的 P0 阻断。P1 为会影响完成核心任务或容易导致用户误判的交互问题，P2 为一致性与可读性优化。以下行号为审查时定位，后续以组件名为准。

### P1-01 会前准备摘要会把失败描述成“0 项未完成”

证据：`Sources/InterviewHacker/WorkspacesView.swift:278` 使用默认折叠的 `DisclosureGroup`，标题只展示 `pendingCount`。`DocumentPreparation.swift:119` 排除 terminal 阶段；`Sources/InterviewHackerCore/DocumentJobs.swift:30` 将 warning、failed、cancelled 都视为 terminal。故队列没有进行中的任务时，失败或待核对仍可得到“0 项未完成”。详细失败与重试藏在折叠区中。

修改：标题使用“会前准备 · 4 份可用 · 1 份处理中 · 1 份需处理”；存在 failed / warning 时默认展开，常驻显示异常数和“查看待处理”。取消单独记为“已取消”，不计为就绪，也不必持续作为红色错误。等待组件和会议中暂停用说明加恢复入口，不伪装为进度停止。列表每行保持文件名、阶段、说明、动作的稳定顺序。

验收：全部 ready、单个 failed、warning、cancelled、paused、部分处理中六种组合中，摘要准确；收起详情仍看得到失败数；失败行的重试在同屏可达。

### P1-02 手机操作没有即时确认反馈，部分错误会被连接更新冲掉

证据：iOS `Mobile/Shared/Sources/CompanionMobileCore/NativeCompanionClient.swift` 的超时和校验失败写入 `connection`，随后 `apply` 会写入“已连接”；网页 `CompanionRelay/src/phone.js` 同样把命令超时写入连接标签。Android 已有独立 `error`，但三端 pending 命令均没有即时可视状态，按钮保持可反复点击。

修改：界面分成两条状态：“局域网 · 已连接”与“正在发送：更简短 / Mac 已确认 / 操作未确认”。前者不能覆盖后者。按下后立即呈现 pending，等 HTTP 成功或已验证 ACK 再标确认；不要因收到普通状态快照就认定命令成功。相同动作 pending 期间抑制重复点击，但停止生成仍可用。超时提示保持到用户处理或后续对应操作成功，重试沿用原命令 ID，避免重复执行。可沿用现有命令模型，不改协议。

验收：请求发出后立即看到反馈；连接心跳不清除失败；断网重试只执行一次；未确认状态不说“已完成”。

### P1-03 手机端“取消”藏在横向操作栏末尾

证据：iOS `CompanionView`、Android `MainActivity.Content`、`Resources/Companion/index.html` 均把 cancel 放在第七个位置，默认窄屏需横滚才能看到。iOS 未展示已存在的 snapshot.position，Android 也未展示，历史切换缺少当前位置提示。网页只在顶部展示位置，和切换控件距离很远。

修改：固定底部主操作为“回答”，生成中切换为“停止生成”；另设短的次级行“更简短 / 举例 / 英文版”。“上一条 / 2 / 5 / 下一条”放到问题或回答头部，使用 snapshot.position；空间不足时改图标并保留可访问名称。使主要操作、停止、历史位置在 320–390 宽度内均无需横滚。三端统一“停止生成”，不要使用含义不清的“取消”。

验收：小屏、横屏、最大字号下停止生成始终可见；查看历史时能看出位置和“回到最新”的入口；操作栏不遮住最后一行回答。

### P1-04 “本次依据”的风险说明不应全部藏在折叠区

证据：`AssistantView.swift:1001` 把资料引用、屏幕、联网与橙色 `evidence.notes` 全部放进折叠区。用户收起时无法发现本次检索/附图等限制。资料引用只展示 citation，没有片段正文。

修改：收起标题摘要为“本次依据 · 资料 2 · 屏幕已附图 · 联网 3”；存在 notes 时在标题下常驻一条“本次回答有 1 项限制”，点击展开完整说明。展开后按“资料 / 屏幕 / 联网”分组，来源名称可选择，资料片段可进一步展开；不要把读取状态推断成模型确实采用了它。继续用对应回答 ID 的冻结依据，历史回答不可展示最新问题的依据。若片段尚未在可用数据中提供，先改善摘要和警告即可。

验收：无资料命中、附图失败、联网失败时收起状态仍有明确说明；切历史后依据同步；回答正文的可视面积不被大量来源挤压。

### P1-05 配对页同时展示三种二维码，首次使用缺少唯一主路线

证据：`SettingsView.swift:449` 的 `CompanionSection` 同时容纳网页、App、HTTPS 备用二维码，端口出现在最前面；手机端要求“设置 → 手机伴侣”，实际设计文档中入口是“高级设置 → 更多 → 手机伴侣”。原生 App 页面又把空配对链接的“连接”突出于“扫描二维码”。

修改：先给“手机网页 / 已安装 App”分段选择；当前选择只展示一个 160–192 pt 二维码、清晰标题与一句使用方式。“扫描二维码”作为手机未配对时唯一主按钮；粘贴链接放次要展开区，空值时禁用连接。端口、蓝牙开关、中转配置归“备用连接与高级选项”，但已启用的备用状态和错误仍常驻可见。中转开启导致需要重新配对时显示就地提示“备用连接已开启，请用新的二维码重新配对”。网页入口不要暗示支持蓝牙。移动端路径文案需与真实入口一致，或者桌面给“连接手机”直达入口。

准确说明：将“屏幕共享完全看不到手机”改为“回答显示在手机；如果共享手机屏幕或将手机镜像到 Mac，仍可能被看见”。把“局域网明文 HTTP”和“互联网加密中转”分别标注在对应入口；不把所有连接笼统描述为明文，也不把 HTTP 标成加密。

验收：首次使用只需决定网页或 App，能找到正确码；开启中转后知道必须重新扫码；扫码失败可粘贴；二维码保持白底、足够留白、不叠品牌装饰。

### P2-01 屏幕面板对“已读取 / 会参与 / 已附图”的区分不够清楚

证据：`InsightsPanel.ScreenSection` 仍使用 `isRelevant` 展示“与对话相关，回答会参考”；新 `ScreenContextService.status` 另有“正在识别 / 画面变化 / 已读取”。来源、识别时间与错误散落在多行，框选区域是否生效缺少简洁摘要。

修改：面板固定显示“来源：窗口名 · 已框选 / 完整窗口”，下一行显示“已读取 · 5 秒前 / 画面变化，等待稳定 / 读取失败”。这里仅描述采集与识别；“本次回答已附图 / 仅文字 / 未采用”留在该回答的依据。出错时提供“重新识别”和“更换来源”，已有内容需明确标记为上次内容而不能显示为新鲜结果。长窗口名可两行，不能把错误截成单行省略。

验收：切换窗口、窗口关闭、切换区域、权限缺失、无文字画面五种状态可区分；来源不会与音频来源混淆。

### P2-02 手机三端的品牌、字号和按钮优先级不一致

证据：桌面 `LiquidGlass.Brand` 使用紫蓝色；网页 `--accent` 为亮蓝，Android 直接用默认 `MaterialTheme`，iOS 使用默认系统色；网页回答默认 20px，原生两端为 22；Android 所有动作都是实心 Button，iOS 都是 bordered，网页只突出回答。三端标签有“简短 / 更简短”“英文 / 英文版”的差异。网页 A−/A+ 仅约 28–32px 高；iOS/Android 使用固定数字字号，尚未看到用户缩放与辅助字体的统一策略。

修改：按下方基线统一语义与节奏，保留各平台原生控件。Android 用已有 Material 3 色系配置单一品牌主色，其余动作使用 tonal / outlined；iOS 主动作 borderedProminent，其余 bordered；网页同等层级。A−/A+ 加“减小 / 增大回答字号”的可访问名称。正文允许系统字体缩放叠加手动倍率；控件和错误信息随系统字体变化。

### P2-03 桌面次要信息过小、胶囊过多，动作禁用态不够统一

证据：历史时间、资料格式、屏幕年龄大量使用 9–11 pt 与 tertiary；既有浅色截图中元数据较淡。`ChipButtonStyle` 和 `GlassIconButtonStyle` 没有像 Primary/Secondary 那样处理 `isEnabled`，可能仍呈现活跃外观。回答区脚下的改写操作水平滚动、二级动作换行，模式不同。

修改：正文不缩小；次要文案统一 12 pt，极次要时间最小 11 pt。优先保留系统 secondary 前景，对重要状态禁用 tertiary。胶囊只用于可点击动作或短状态，不给长说明加壳。补一致禁用样式，保留其标签且不给可点击反馈。常用改写最多显示三项，其余进“更多”；按钮行断点与回答区宽度对应，避免半个标签被切掉。

## 统一设计基线

| 项目 | macOS | 手机原生与网页 |
|---|---|---|
| 字体 | 系统字体；页面标题 20–22，模块标题 14–15 semibold，正文 13–14，回答 16–18，说明 12 | 系统字体；标题 20，问题 17–18 semibold，回答默认 22，说明 13–14；支持系统字体缩放 |
| 行距 | 回答增加 4–6 pt；长说明可自然换行 | 回答 1.5–1.6 倍；单列满宽，正文不居中 |
| 间距 | 基础 4；行内 8；组内 12；卡片 16；区块 24 | 左右 16；组内 12；区块 24；保留安全区 |
| 圆角 | 内容卡片 16–20；输入 8–10；动作 10–12，沿用现有胶囊亦可但不新增层数 | 内容卡片 16；按钮 12；原生系统圆角优先 |
| 表面 | 中性底色、可读实色内容面；品牌色只出现在主动作与选择态；渐变限品牌小元素 | 浅深主题使用系统 surface；不把背景设为大面积品牌色 |
| 品牌色 | 保留现有紫蓝作为识别色；小号白字按钮采用更深主色并验证对比度 | 候选主动作浅色 #5146C8、深色 #5754D8；链接颜色另按主题验证，不强制所有平台同一 hex |
| 主动作 | 高 36，最多一个强强调动作/任务区 | iOS / web 触控目标至少 44×44；Android 至少 48×48 dp |
| 状态 | “图标 + 文字”，颜色辅助 | 同左；连接状态和操作状态独立；离线仍保留最近答案并标明其非实时 |
| 成功 | 勾选图标 + “已就绪 / 已连接”，系统绿色 | 不把静默备用误标为当前正在使用 |
| 进行中 | spinner + 明确阶段，可取消时就地显示取消 | “发送中 / 等待 Mac 确认 / 生成中”分别表达 |
| 警告 | amber 图标 + 可操作说明，不以颜色独传 | “已降级为关键词 / 正在使用备用连接”不等同于失败 |
| 错误 | red 图标 + 原因 + 一项恢复操作；错误文案可换行 | 失败不被常规状态刷新覆盖；细节可展开但主要原因常驻 |
| 空态 | 单个系统图标 28–32 + 一句作用 + 一个下一步动作 | “连接 Mac 后，当前问题和回答会显示在这里”；等待与断开使用不同文案 |
| 动效 | 100–180ms 状态变化；减少动态效果时禁用缩放/弹簧 | 不给流式正文整块淡入；不自动滚动打断用户阅读历史 |

颜色为建议值，合入时需要在真实背景和浅深主题下测量正文/按钮对比度；已对最终网页 CSS 的实色 RGB 值做静态对比度计算（见末节），尚未对所有平台实际合成背景执行视觉/辅助功能验收。跨端一致性优先统一信息、状态和操作顺序，再匹配色相，避免强迫 SwiftUI 与 Material 变成同一种仿制界面。

## 建议实施顺序与验收材料

1. 修正准备摘要、常驻依据警告、操作 pending/确认/失败、手机停止按钮四项状态问题。
2. 把配对拆成两种明确入口，准确标注每条连接的性质与重新配对条件。
3. 统一手机答案布局、按钮文字、历史位置和触控目标；再调整桌面次要字号与禁用态。
4. 固定截图场景：桌面 1280×800 与最小支持窗口；手机 320×568、390×844 和横屏；浅色、深色、最大辅助字体、离线/失败/等待/正常生成。截图必须标明 demo、模拟器或真机，不能互相替代。

建议交付截图至少包含：资料成功与失败并存、无命中回答并展开依据、框选屏幕与失效来源、网页/App 配对两种模式、手机生成中且停止可见、命令超时后连接仍恢复但错误未丢失。

## 美术资产决策

本轮不新增插画或生成图。核心问题是信息与交互，已有 SF Symbols / Material 图标足够表达资料、屏幕、手机与状态。新增位图会增加包体与浅深主题维护成本，且不帮助完成配对和阅读。若后续需要统一网页图标，使用 20 / 24 viewBox、1.75–2px 单色描边 SVG；仅为实际使用的断开、重连、资料、屏幕来源设计，不给二维码加装饰。
